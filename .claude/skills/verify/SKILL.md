# 검증

**구현했다 ≠ 완료했다.** 이 스킬은 완료를 판정한다.

## 1. 실행

```bash
./scripts/verify.sh
```

빠른 확인만 필요하면 (앱 빌드 제외. HotChaKit 은 그대로 돈다):

```bash
./scripts/verify.sh --quick
```

사람·Claude·Git Hook 이 **모두 이 명령 하나**를 쓴다. 각자 다른 명령을 쓰면 "내 쪽에서는 됐는데"가 생긴다.

## 2. 검사하는 것

| 단계 | 내용 | 실패하면 |
| --- | --- | --- |
| Xcode 버전 | 로컬 메이저가 `.xcode-version` 과 같다 | **차단** |
| 프로젝트 규칙 | 목록은 `./scripts/check-project-rules.sh --list` | **차단** |
| 코드 포맷 | `swift format lint` | 경고만 |
| SwiftLint | `--strict` (설치 시) | 차단 |
| **HotChaKit** | `swift test` — 알람 규칙의 방어선. 시뮬레이터 불필요 | **차단** |
| iOS 빌드 | 앱 + Live Activity, 처음부터 컴파일 | **차단** |
| **빌드 경고 0** | 컴파일러 경고를 직접 센다 | **차단** |

규칙의 개수를 이 문서에 적지 않는다. 적어 두면 반드시 어긋난다. 셈은 검사기만 한다.

### 검증이 확인하지 **못하는** 것

- **앱 타깃에는 테스트가 없다.** 화면·위치 추적·알림·Live Activity 는 빌드가 되는지까지만 본다.
- **프로젝트 규칙은 grep 이다.** "어떤 글자가 어디 있는가"까지만 답한다. 규칙 통과 ≠ 올바름.
- 알람이 **언제 울리는지**는 `HotChaKit` 테스트만 안다.

화면이나 알람 동작을 고쳤으면 시뮬레이터에서 직접 돌린다. 위치는 이렇게 옮긴다:

```bash
xcrun simctl location booted set <위도>,<경도>
```

### 초록이 거짓말할 수 있는 지점

- **테스트가 0건 돌고도 성공한다.** `verify.sh` 는 `Test run with N test` 를 세고 0 이면 실패시킨다
- **검사기 경로가 어긋나면 전 규칙이 무탐지로 통과한다.** 규칙 0 이 훑은 파일 수와 핵심 테스트 존재를 먼저 확인한다
- **증분 빌드는 안 바뀐 파일의 경고를 다시 찍지 않는다.** 검증은 `clean build` 로 처음부터 컴파일한다

## 3. 실패했을 때

1. **무엇이 실패했는지 그대로 읽는다.** 추측하지 않는다
2. 30분 넘게 막히면 찍어보기를 멈추고 → 재현 → 범위 좁히기 → 근본 원인 → 증명
3. 알람 규칙 문제면 **재현 테스트를 먼저 쓰고** 실패를 눈으로 본 뒤 고친다

## 4. 보고

통과했을 때만 완료라고 말한다. 보고에는 숫자를 넣는다.

```
✓ 프로젝트 규칙 통과 · HotChaKit 15건 · iOS 빌드 · 빌드 경고 0
```

**금지**
- "아마 될 거예요"
- 실행하지 않고 "고쳤습니다"
- 새 테스트만 돌리고 "통과"

## 5. 확인하지 못한 것은 확인하지 못했다고 쓴다

시뮬레이터에서 눈으로 못 본 항목, 실기기에서만 확인되는 항목(백그라운드 위치·소리·진동·잠금 화면)은
✅/⚠️ 로 나눠 적는다. 다 됐다고 뭉뚱그리지 않는다.
